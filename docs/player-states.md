# 玩家状态与扶起

服务器维护四种本局身份：`ALIVE`（存活）、`DOWNED`（倒地）、`ELIMINATED`（阵亡）、`SPECTATOR`（观战）。WAITING 没有本局身份。所有身份、死亡锚点、截止时间和扶起进度只保存在当前逻辑服务器的内存中，不写 SavedData、玩家 NBT 或装备存储。

## 开始与结束

- 等待时用 `/runelegend player spectate true` 选择下一局观战，用 `false` 取消；`/runelegend player status` 查询。选择在等待阶段断线后仍保留，开局时消费，运行中无法调整。
- 开局为全部在线玩家统一分配身份：参与者 ALIVE／冒险模式，观战者 SPECTATOR／旁观模式。中途首次加入为 SPECTATOR，并沿用原版保存位置上线；只有 WAITING 登录会传送到世界出生点。
- ALIVE 或 DOWNED 断线直接转 ELIMINATED，身份保留到本局结束；重连保持阵亡，原观战者仍观战，不能通过重连复活。
- 没有 ALIVE 参与者时，在服务端 tick 汇总阶段自动调用原有停局流程；最后一人倒地也会立即结束本局，不继续等待倒地超时。全员观战的开局同样自动结束。
- 手动和自动停局都回到 WAITING，清空包含离线玩家的本局身份、倒地记录、计时、救援关系和观战选择。在线玩家统一传送到世界出生点，改冒险模式，生命、饥饿、体力回满。WAITING 登录同样初始化并在世界出生点上线，忽略上次退出时的位置。世界出生点由服务器的世界出生数据决定，通常用 `/setworldspawn` 设置；不会传送到模组自定义的大厅。
- 游戏模式只在登录、实体替换和状态转换时设置，不每 tick 覆盖管理员的修改；更改模式不会改变逻辑身份。旁观模式玩家也不能触发令牌或救援。

## 倒地与救援

原版不死图腾判定失败后，服务器在 `ServerPlayer.die` 入口拦截 RUNNING 玩家的真实死亡。ALIVE 变为 DOWNED，保留物品、装备和经验，不出现死亡界面，不计死亡统计。清除普通药水、局内令牌状态、火焰／冻结／跌落等即时残留，切旁观模式并记录死亡瞬间的维度、精确坐标和朝向。WAITING 死亡继续走原版流程。

倒地者可以飞行或更换维度，救援始终以死亡锚点为准。ALIVE 救援者需要与锚点同维度，脚部位置的三维距离不超过配置值，并持续发送潜行输入。不要求视线、朝向或 scoreboard 队伍。每名目标和救援者最多各占用一个救援关系；有效关系保持优先，空闲关系按距离、目标 UUID、救援者 UUID 稳定匹配。

停止潜行、离开距离、救援者死亡／断线／换维度／实体替换会清空进度，重新开始必须完整计时。死亡截止时间和救援完成发生在同一 tick 时，阵亡优先。

扶起成功时，目标传回死亡维度附近的安全站立点，恢复配置比例的当前最大生命值，转冒险模式和 ALIVE，并删除倒地记录、计时和显示。搜索范围为水平 4 格、上下 3 格，按距离排序；仅检查已加载区块、普通站立碰撞箱、支撑面、世界边界、液体和常见危险方块。找不到安全点时直接使用原始死亡坐标。维度不可用或传送失败时不提交 ALIVE，清空本次救援，倒计时继续。

原地兜底可能再次遇险，不额外增加无敌或更改地形。停局和 WAITING 登录会把玩家送回世界出生点；关卡应把世界出生点设置为安全的等待区，不要依赖玩家各自的床或重生锚。

## 显示和同步

死亡坐标上方约 2 格显示「潜行以扶起队友」和「阵亡倒计时：N 秒」，同维度玩家和旁观者均可见，64 格裁剪。提示使用穿透方块的世界文字管线绘制，带阴影和半透明背景框，被方块或地形遮挡时仍然可见。文字由客户端世界渲染绘制，无额外 TextDisplay 实体。

服务端沿用本人快照／增量的 revision 链同步状态和当前维度标记；标记增加、移除和剩余整秒变化时发送变化部分。客户端不决定状态或救援结果，也不自行计时删除标记。协议失序时隐藏不可信数据并请求原有重同步；停局、断线、切服务器和新会话清空缓存。扶起进度不上传、不显示进度条。

## 配置

路径：`<游戏实例>/config/runelegend-core/player_states.json`。逻辑服务器启动时读取一次，不提供热重载；单人世界共用实例配置，但状态互不共享。

```json
{
  "schemaVersion": 1,
  "revive_distance": 2.0,
  "revive_duration_seconds": 2.0,
  "downed_duration_seconds": 15,
  "revive_health_percent": 50
}
```

距离必须为有限正数且平方有限；持续时间支持正小数秒，以 `ceil(秒数 × 20)` 换算 tick，最多 `Integer.MAX_VALUE` tick；生命比例须为有限数且在 `(0, 100]` 内；schemaVersion 必须为整数 1。不要求救援时长短于倒地时长。计时随服务器 tick 推进，低 TPS 会延长实际耗时，服务器暂停不推进。

文件缺失时生成默认配置，缺字段使用该字段默认值。非法 JSON、类型、版本或数值使整份配置回退默认值并记录错误，不覆盖原文件。默认文件写入失败时仍使用内存默认配置。

## 扩展与验证

`RuneLegendServer` 组合 `PlayerStateService`、`DownedService` 和 `RevivePositionResolver`。未来救援令牌可以查询不可变倒地记录，使用 `RuneLegendServer.revive(UUID, downedSequence)` 进入统一完成路径；本次没有救援令牌，也没有绕过 ALIVE 目标检查的通用开关。普通令牌在调度和执行时均验证当前连接、身份、回合和运行态代次；清理可重复调用，不删除已佩戴令牌或装备数据。

验证入口为 `gradlew.bat test`、`gradlew.bat build runClientGameTest`。相关覆盖包括配置回退、身份生命周期、一对一连续救援、超时优先、图腾与物品保留、重连、原地兜底、停局与等待期世界出生点传送（含跨维度）、网络增量和客户端标记清理。与其他模组同时拦截死亡时，需要针对其回调顺序另行做兼容验证。
